# Native PostgreSQL recovery integration

Objective: Export one consistent complete PostgreSQL snapshot plus the exact immutable object references visible in that snapshot, then restore objects and relational evidence only to a deliberately created empty local recovery DB.

Base SHA: `6e30570`; integration branch `codex/durable-evidence-recovery`.

Owned files: `mira/database_recovery.py`, `tests/test_database_recovery.py`, this handoff. Explicit related extension assignment also authorized `mira/recovery.py`, `tests/test_recovery.py`, and its handoff for strict legacy report `relative_path` preservation. No shared CLI/provider/SQL/artifact file edits. Read-only dependencies: package API, repository ownership/design instructions, `mira/db.py` and test conventions.

Interfaces:

- `PgTools(dump_command=('pg_dump',), restore_command=('pg_restore',), timeout_seconds=120)`. Prefixes accept tuples/lists of safe argv and support trusted operator Docker wrappers; no shell. Native executables must be named `pg_dump`/`pg_restore` (absolute binary paths are accepted). Timeout must be finite and positive. A strict transport grammar permits only exact `--host`, `--port`, `--username` and `-h`, `-p`, `-U` options, with separate/attached values. Hosts must be loopback or canonical absolute local Unix socket paths; ports/usernames are validated. Unknown flags, abbreviations, native positional files, `--`, destructive short bundles and all scope filters are refused. Docker wrapping is exactly `docker exec [-i|--interactive] <container> <native-tool> <transport-options>`; isolated fixture injection supports a Python/PyPy runtime plus one literal `.py` filename. Connection strings and password arguments are refused. Prefixes are trusted executable configuration and must address the same cluster as the supplied psycopg connection/target DSN.
- `backup_database(conn, destination, *, collect_objects, read_object, tools=PgTools()) -> dict`. Requires an idle psycopg connection. Opens one REPEATABLE READ READ ONLY transaction, exports its snapshot, calls `collect_objects(conn)` in that transaction, and streams `pg_dump --format=custom --snapshot=<id> --dbname=<name>` to a private 0600 temporary file. Output is bounded to the package's 2 GiB DB limit and tool timeout, and failed/timed-out children are killed and reaped. Calls `create_backup` while the exporting transaction remains active. Collection must use the supplied connection, return a sequence of JSON identities, and preserve transaction ownership.
- `restore_database(archive, target_dsn, *, write_object, tools=PgTools(), trusted_backup: bool=False) -> dict`. It refuses unless `trusted_backup is True` before package processing, native tools, connections or object writes. Native `pg_restore` executes SQL with the target role permissions; checksums authenticate neither the author nor the SQL. Only operator-created trusted archives may receive explicit acknowledgement. Returns only `{schema_version: 1, database_restored: True, object_count: N}`. Verifies the complete package before connecting to a target or writing objects. Requires explicit loopback host/hostaddr and target name `mira_recovery_<32 lowercase hex>` or the isolated test namespace `mira_recovery_test_<32 lowercase hex>`; no remote/multiple-host/service/unknown DSN options. Hostaddr is pinned to loopback to defeat ambient libpq redirection. A bounded private `pg_restore --list` reads the native source-db header, and an equal source name is refused even after that source was emptied/closed.
- Before callbacks, the target must have no other sessions, user tables/views/sequences/functions/types/schemas, nondefault extensions, foreign servers or large objects. A cooperating-worker advisory lock is held through restore. Target emptiness is checked again after object writes. Database publication uses native `pg_restore --exit-on-error --single-transaction --dbname=<name>` with no `--clean`, `--create`, owner/grant stripping or data filtering. Objects restore before the database callback, preserving exact identities and legacy report paths.
- `DatabaseRecoveryError` derives from package `BackupError`; package validation and callback errors retain their respective typed errors. All exposed failures have static secret-free messages. `PGPASSWORD` and connection parameters are environment-only; subprocess stderr/stdout never reaches logs. Native dump bytes are private files; private listing output is discarded. This module never creates/drops a database, applies migrations, changes grants, or performs an in-place restore.

Open risks: This is local recovery, not cloud replication or cross-service atomicity. Earlier successful object writes may remain after later restore failure. The caller supplies complete reference enumeration and an idempotent writer that rejects mismatched immutable identities. Server roles and extension binaries/dependencies must exist; database-level owner/locale/server configuration and cluster-global roles are operator prerequisites, not created here. Tool wrappers are trusted operator configuration; Docker/native command mappings must point at the same cluster the guard inspects. Target checks exclude concurrent sessions at check time and serialize cooperating workers; operators must keep the fresh recovery DB exclusive throughout the operation. Keep the verified archive exclusively owned through restore. The native source listing is capped at 8 MiB and parsed from its first 64 KiB; unusually large/unsupported archives fail closed. A wrapper child is killed/reaped on timeout; a Docker server-side process is outside direct OS-child ownership and should terminate after its closed pipe. No production backup or full Mira-schema restore proof is claimed by the synthetic drill.

## Independent-review correction

The initial denylist accepted native options such as `--exclude-table=public.document_passages`, `--exclude-table-data=...`, `-T...`, `-N...`, `-tpublic.reports`, `-Llist.txt`, `--use-list=...`, and unknown bundled/abbreviated options. That could permit incomplete evidence packages or altered restore behavior. It was replaced by the strict transport-only grammar above; no reviewed bypass option is executed by the regression tests. Source DB names are also constrained to safe PostgreSQL identifiers before appending a native `--dbname` argument. Native connection prefixes cannot override the local target guard with a remote host.

The restore API additionally requires explicit `trusted_backup=True`. Package checksums detect damage but do not make arbitrary native archive SQL safe to execute. Existing actual restore tests acknowledge only their own newly created synthetic archives. The generic package restore callback API has no PostgreSQL trust policy and is unchanged.
