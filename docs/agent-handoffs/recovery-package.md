Changes:

- `BackupObject(identity: dict)` validates/copies a JSON identity. Required fields: canonical UUID-string `workspace_id`, `purpose` (`original`/`report`), lowercase SHA256 `sha256`, integer `size_bytes`, nonblank `media_type`, `storage_kind` (`private_local`/`private_supabase`). Optional keys `approval_reference` and `bucket` are accepted. Optional `relative_path` is allowed only for `purpose=report` plus `storage_kind=private_local`, and must match a canonical lowercase UUID directory followed by `report-v[1-9][0-9]*(-reviewed)?.html`. It preserves legacy database artifact paths without changing frozen snapshots; arbitrary metadata/credential fields are rejected.
- `create_backup(destination: Path, database_dump: Path, objects: Sequence[dict], read_object: Callable[[dict], bytes], *, max_database_bytes=2147483648, max_object_bytes=20971520, max_objects=100000) -> dict`. The caller supplies a consistent native dump; the package copies it byte-for-byte in bounded chunks. It checks every reader result, deduplicates byte files by digest, preserves distinct workspace/purpose identities, verifies the whole staged package, then publishes it with native no-replace atomic directory rename. macOS and Linux supported; other platforms fail closed. Package directories use 0700; files use 0600. Existing destinations, including ones appearing during creation, are preserved.
- `verify_backup(path: Path, *, max_database_bytes=2147483648, max_object_bytes=20971520, max_objects=100000) -> dict`. Canonical schema-v1 `manifest.json` is capped at 8 MiB; `.complete` contains its SHA256 plus newline. Files are `database.dump` and `objects/<sha256>.bin`. Every absolute directory component and member is opened without following symlinks. Parent traversal, unknown schema/keys, duplicate JSON keys, duplicate logical identities (workspace/purpose/hash/relative_path), incompatible repeated identities, unexpected/missing files, malformed types, oversized files, and content changes fail closed. File enumeration is bounded.
- `restore_backup(path: Path, *, write_object: Callable[[dict, bytes], None], restore_database: Callable[[Path], None]) -> None`. Fully verifies all members before the first callback, writes objects under their preserved identities, and calls the database restore once only after all object writes succeed. An object failure stops before DB restoration. Read/creation/validation errors are typed `BackupValidationError`; callback errors are `BackupRestoreError`; both derive from `BackupError` and use static input-free messages.

Open risks: Checksums detect integrity damage, not malicious package authorship; no signing/encryption is claimed. The caller must ensure consistent dump generation, complete relational-reference enumeration, fresh empty local DB targeting, exclusive package ownership during restore, and idempotent object writers that reject preexisting mismatched immutable identities. External object writes and DB restoration are not atomic together; successful earlier object writes may remain after later failure. Publication requires POSIX macOS/Linux native no-replace rename support. The 8 MiB manifest bound can constrain the practical object count below the 100000 entry ceiling. No cross-service rollback, remote recovery, or production backup proof is claimed.
