# Actual live browser acquisition under explicit source permission

Base: PR7 head `9fc110b`; preserve integrated main/PR6 numeric quote, scout token/category seeding and coverage safeguards. User explicitly authorizes implementation and PR7 update. Existing isolation and branch are suitable. No feature reapproval or model configuration change. No paid/model/Exa validation calls.

## Intent and choices
The previous offline HTML renderer cannot acquire a page that ordinary HTTP cannot read. Add a real Chromium browser that navigates, executes permitted public-page JavaScript and performs up to three curator-configured read-only click/wait actions. This is deterministic browser automation, not a new paid model-driven computer-use agent. Reuse the existing saved-evidence, semantic verification and frozen reviewed report paths.

Chosen: a separately enabled browser acquisition adapter with code-owned source/network/action policy and killable process boundary. A broad unrestricted browser or stealth/CAPTCHA bypass is rejected; routing all resources through the old HTTP downloader would retain its acquisition failure and is not a live-browser solution. Keep the old offline adapter separately available.

## Permission and acquisition contract
`MIRA_ENABLE_LIVE_BROWSER=1` enables the adapter globally; it grants no source permission. A source must already permit fetch and store_text and explicitly configure `allow_live_browser=true`, `browser_access_approval.reference`, and the appropriate approved browser operations. Blocked-HTTP fallback additionally requires `browser_access_approval.allow_http_block_fallback=true`. Disabled/missing approval fails closed. Robots, private-network and out-of-source refusals never trigger browser retries; 429 does not trigger browser retry. A browser that itself receives a block, CAPTCHA, login/access denial stops. No imported sessions, credentials, stealth or challenge solving.

MAS currently has no established browser-access/storage approval, and the repository explicitly says not to work around its bot block. The user explicitly answered to keep MAS disabled and test a permitted source in another country. Do not change MAS seeded permissions or perform a live MAS acquisition. Check Hong Kong HKMA current terms/robots and use a separately bounded non-commercial public browser validation if allowed. Independent implementation and fixture tests proceed regardless. Public policy checks are distinct from acquisition permission.

`LiveBrowserAcquirer.acquire(url, *, sources, source_ids, timeout_seconds, reason) -> LiveBrowserResult(page: FetchedPage, provenance: dict)` accepts a fresh workspace source catalogue and explicit task IDs. A pure eligibility helper supports preflight before charging. It returns the final rendered DOM as browser capture, not a complete archived publisher original. A source controls a maximum-three bounded read-only action sequence. The browser performs no user-supplied typing, arbitrary evaluation, credential entry or write requests.

Every navigation, redirect and subresource must satisfy approved host/task/source/public-address/robots/rate policies. Pin vetted DNS addresses for browser requests, reject unapproved hosts and private/loopback targets. Block service workers, WebSockets, WebRTC, popups and downloads; allow only GET/HEAD. A fresh isolated context prevents cross-workspace/run session reuse. Bound wall time with process-group cancellation, request count and captured DOM size; monitor cumulative network bytes and abort when the observed cap is crossed (a delivered transport chunk may overshoot, so this is not a pre-receipt packet cap). Preserve failures and sanitized request/action/resource logs.

## Integration and budgets
HTTP remains first. On eligible HTTP failure or unreadable JavaScript page, acquire through the browser only with remaining document/time allowance and explicit permission. Log and charge the HTTP attempt and the separate browser attempt; refused preflight sends no request and consumes no acquisition slot. Never erase the original failure. Persist successful browser evidence before any model reads it, with current source permissions rechecked under the existing writer transaction/deadline. An unusable original HTTP capture may be saved as a visible failure before browser acquisition. Preserve per-workspace/run successful URL deduplication and Ewen's selection/report token controls.

Corroboration uses the same permitted adapter and charges both attempts through DiscoveryBatch accounting. Its hard deadline and shared run budget continue to cap acquisition. The existing broker may signal a failed HTTP read so the parent performs a separately killable browser acquisition; no browser child may escape cancellation. Current source permission rechecks and exact latest eligible saved-version selection remain mandatory.

## Implementation boundary decisions
Use a real Chromium request path, not the old downloader to fetch page resources. Child robots transport connects to pinned vetted public IPs while retaining original Host/TLS verification; browser DNS uses the same approved mapping with unknown hosts rejected. Parent source-host locks serialize browser acquisition against HTTP requests; child inherits conservative timing and returns observed robots delay, which parent HTTP scheduling must preserve. An observed-byte monitor may abort after one delivered chunk; request/DOM limits and process-group wall deadline remain strict. No CONNECT proxy is required. Live browser is controlled deterministic navigation/interaction, not an additional model API integration.
