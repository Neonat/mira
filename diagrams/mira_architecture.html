DBS Internal Audit · External Driver Researcher · Prototype

How Mira works

Mira is a research assistant for internal auditors. An auditor picks a topic and the jurisdictions. Mira reads approved regulator and industry sources and returns a draft report in which every statement links to the passage it came from. A person reviews the draft and signs it off.

Design principle: AI models read and draft. Ordinary code decides what may be read, checks every claim against the saved source, and records every step. Prototype scope: AML/CFT in Singapore and Hong Kong.

1 · The brief

What DBS asked for, and how Mira answers it

DBS requirementHow Mira meets it
An agentic tool: choose a topic and jurisdictions, get a structured report on regulatory and industry developmentsFive AI agents (planner, scouts, analyst, verifier, writer) work in a fixed sequence that code controls. The report has fixed sections: summary, regulatory changes, deadlines, jurisdiction comparison, industry trends, impact on the bank.
Accuracy and traceability: every statement links to its sourceEach page is saved before any AI reads it. Each statement in the report cites a saved passage, the exact document version, and the original web address.
Completeness: coverage is checked, not assumedA checklist of sources that should be covered for each jurisdiction. Code checks which were actually read, retries missing ones, and prints any remaining gaps in the report.
Hallucination detection: unsupported claims are caughtEach claim is checked twice: code confirms the quoted words really appear in the source, then a separate AI checks the meaning. Claims that fail never appear in the report body.
Human oversightThe report stays a watermarked draft until a reviewer has accepted, amended or rejected every finding and signed off.
2 · The system

The system at a glance

Mira has three parts: a web app for the auditor, a database, and a background worker. The app never talks to the AI or the internet. It only records requests in the database. The worker picks them up, does all AI calls and web reading, and saves every result back.

3 · One run

What happens when an auditor asks a question

AI step Code step Person
  1. Brief. The auditor chooses a topic, jurisdictions and a time period in the web app.
  2. Plan. An AI planner decides which approved sources each scout should read. Code rejects a plan that skips a source on the checklist or sends a Singapore task to a Hong Kong source. An analyst can be required to approve the plan first.
  3. Gather. Scouts (one per jurisdiction, plus one for industry bodies) read the sources. The AI chooses which links matter. Code does the fetching and saves each page before the AI sees it.
  4. Completeness. Code compares the checklist with what was actually saved. A scout claiming it found something does not count without the saved page. Missing sources get another attempt, and anything still missing is listed in the report.
  5. Draft claims. An AI analyst reads the saved passages and writes claims. A fact must quote its source word for word. An inference (a risk, trend or comparison) must name the facts it rests on.
  6. Check claims. Every claim goes through the checks in section 4.
  7. Write. An AI writer turns verified claims into the report sections. Code rejects any sentence that cites something not verified.
  8. Review. The report carries a DRAFT watermark. A reviewer records a decision on every finding. The system will not allow sign-off until each one has a decision.
4 · Hallucination control

How a statement earns a place in the report

Two checks, cheapest first. The first is plain code and catches invented quotes. The second is a separate AI, with no memory of how the claim was written, that catches real quotes stretched to mean something they don't (a wrong date, or "in force" when a rule is only proposed).

5 · Sources

Where Mira looks

Mira may contact only the 15 sources on its approved list. For each one, the list records how Mira can get its documents and whether it may store and quote the text. A source Mira can read but not quote still counts toward coverage, but no claim can cite it.

6 · Evaluation

How we will show it works

Using several agents costs more than using one, so the evaluation has to show the extra cost is worth it. The same question is run through three designs and each is scored the same way.

DesignWhat it does
Plain search (baseline)Keyword search over the saved documents. No AI.
Single agentOne AI does the research in one pass, with only the quote check.
Multi-agent (Mira)The full design above: a planner, scouts per jurisdiction, repeat attempts for missing sources, and both checks.

Coverage

≥ 80%

Share of 24 real AML/CFT developments (an answer key compiled by hand for this period) that the report finds and cites.

Precision

≥ 95%

Share of reported claims a person confirms against the source. A sample of claims is labelled with the design's name hidden, so the labeller does not know which design wrote each claim.

Time saved

≥ 50%

Time for an auditor using Mira, including review, compared with doing the same research by hand.

Decision rule: the multi-agent design must beat the single agent on coverage or precision to justify its cost. Early check: the single agent must find at least half of the answer-key items it can reach before full evaluation goes ahead. The scoring code refuses to give a verdict from anything except live AI runs, so test data cannot produce a result.

Reference

Key terms

Approved list
The only sources Mira may contact, each with what it is allowed to do: read, store text, quote.
Checklist
The sources that should be covered for a topic and jurisdiction. Completeness is measured against it.
Passage
A short section of a saved document. The smallest thing a claim can cite.
Fact / inference
A fact quotes a passage. An inference (risk, trend, comparison) is built only from verified facts.
Unresolved
A claim that failed a check. Shown under limitations, never stated as fact.
Partial run
A run that hit its budget. Its report says so and lists what was not covered.
